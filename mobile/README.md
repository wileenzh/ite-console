# ITE mobile app (iOS and Android)

The store app is the ITE console packaged with [Capacitor](https://capacitorjs.com) 8. It uses the same data, sign-in
and settings as the console. On a phone, each role gets its own home screen and bottom tabs:

| Role | Opens on | Tabs |
|---|---|---|
| Security guard | My duties: current shift, **Clock in / Clock out** | Shift · Patrol · Report (flag to the PSOC with photo and location) · Alerts for my site |
| Site security manager | Site security manager: shift board, five layers, site risks | Site · Roster · Risk · Cameras (video wall) |
| DSOM (country) | Country view | Country · Decisions · Workforce · Sites |
| RSOM (region) | Regional view | Region · Decisions · Risk · Workforce |
| APAC director | APAC director overview | APAC · Decisions · Risk & value · Campuses |
| PSOC officer | Home: what needs you now | Home · Map · Queue · Incidents |

People choose their role the first time they open the app, and can change it under **More › My role in the app**. A
security patrol officer account is always a security guard, and a leadership account is always the APAC director.
Every tab also has **More**, which lists every screen the account may see.

What the app adds on the phone:
- **Shift reminders:** a notification one hour before each booked shift, rescheduled whenever shifts change.
- **Haptics** when you clock in or out, pick up a shift, send a flag or answer a decision.
- **Android back button:** it closes the open window or menu, then returns to the first tab, then leaves the app.
- **Status bar and splash screen** in the app's colours; the map library is bundled so the map starts offline.
- **Camera and location** for reports to the PSOC: a photo is attached, and the location is added to a flag.
- **Push notifications**, once your Firebase (Android) and Apple Push (iOS) keys are added (see below).

## Project layout

```
mobile/
  package.json             Capacitor 8 and its plugins (exact versions)
  capacitor.config.json    app id, name, splash and notification settings
  scripts/build-web.mjs    builds www/ from ../index.html (bundles Leaflet)
  scripts/make-art.cjs     draws the icon, adaptive icon layers, splash and notification icon
  resources/               the artwork used to generate every icon and splash size
  android/                 Android Studio project
  ios/                     Xcode project (Swift Package Manager, no CocoaPods)
```

`www/` and the copies Capacitor puts inside the native projects are generated by the build, so they are not committed.

## Build it

The project needs Node 22. Android builds also need Android Studio (or JDK 21 plus the Android SDK), and iOS builds
need a Mac with Xcode 16 or newer.

```bash
cd mobile
npm ci
npm run android     # builds www/, copies it into android/ and opens Android Studio
npm run ios         # same for Xcode (on a Mac)
```

After the console changes, run `npm run sync` to copy it into both apps.

**GitHub builds it automatically.** `.github/workflows/mobile.yml` runs on every push that changes the console or this
folder:
- **Android:** a debug APK for test phones, saved on the run as `ite-android-debug-apk`. When the signing secrets below
  are set, it also makes a signed `.aab` for Google Play (`ite-android-release-aab`).
- **iOS:** a simulator build that proves the project compiles.

To get a build: open the repository on GitHub › **Actions** › **Mobile app**, then the latest run, then
**Artifacts**. The debug APK installs on an Android phone once installing from unknown sources is allowed.

## Before the first store release

1. **App id.** `io.github.wileenzh.ite` is a placeholder. Change it to your organisation's reverse domain (for example
   `com.<org>.ite`) in `capacitor.config.json`, in `android/app/build.gradle` (`namespace`, `applicationId` and the
   `MainActivity` package folder) and in Xcode (Signing & Capabilities › Bundle Identifier). Store ids cannot change
   after the first release.
2. **Decide how it is distributed.** This is an internal security tool, so a public listing is usually not wanted:
   - **Apple:** TestFlight for pilots (up to 10,000 testers). For production, a **Custom App** through Apple Business
     Manager, which is private to your organisation and still reviewed by Apple, or the Apple Developer Enterprise
     Program for in-house distribution.
   - **Google:** an internal testing track for pilots, then a **private app** in managed Google Play for your
     organisation's devices.
3. **Accounts:** an Apple Developer Program membership (US$99/year) and a Google Play Console account (US$25 one-off).
4. **Privacy policy URL**, required by both stores. The app handles:
   - sign-in name and role;
   - shift and training records entered by the user;
   - photos attached to reports;
   - the location attached to a flag, sent only when a flag is sent;
   - the device push token, if push is enabled.

   Nothing is used for tracking or advertising. Use the same answers for Apple's App Privacy section and Google's Data
   safety form.
5. **Reviewer access.** Apple and Google review the app. Give them a test sign-in that opens a profile with sample data
   (Manpower & training › **Load sample workforce**), and note that the app is for an organisation's security team.

## Android release (Google Play)

1. Create the upload key once and keep it safe; losing it means contacting Google to reset it:
   ```bash
   keytool -genkeypair -v -keystore ite-upload.jks -alias ite -keyalg RSA -keysize 2048 -validity 10000
   ```
2. In GitHub › Settings › Secrets and variables › Actions, add:
   - `ANDROID_KEYSTORE_BASE64`: the output of `base64 -w0 ite-upload.jks`;
   - `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`ite`) and `ANDROID_KEY_PASSWORD`.
3. Push, then download `ite-android-release-aab` from the run. Upload it in Play Console › your app › Testing ›
   Internal testing, with Play App Signing turned on.
4. **Push (optional):**
   - create a Firebase project and add an Android app with the same id;
   - put its `google-services.json` in `mobile/android/app/` (the build picks it up automatically);
   - turn on **More › Push notifications in the store app** (shown to admins);
   - the app sends its push token to the PSOC server at `/api/push/register`, and the server sends alerts through
     Firebase Cloud Messaging.

## iOS release (App Store, TestFlight or Custom App)

1. On a Mac: `cd mobile && npm ci && npm run ios`.
2. In Xcode, open **App › Signing & Capabilities**:
   - choose your team;
   - set the bundle identifier;
   - add **Push Notifications** and **Background Modes › Remote notifications** if you use push.
3. Choose **Product › Archive**, then **Distribute App › App Store Connect** and upload.
4. In App Store Connect, add the build to TestFlight, or submit it for review (as a Custom App for Apple Business Manager
   if it should stay private).
5. **Push (optional):** create an APNs key in your Apple Developer account and add it to the PSOC server's push
   settings (or to Firebase, if you use Firebase for both platforms).

The camera, photo library and location messages iOS shows are already in `ios/App/App/Info.plist`.

## Updating the app

Most changes are to the console (`index.html`). The app carries a copy of it, so users get those changes when a new
build is released through the stores or TestFlight. Live data (hazards, alerts, decisions, shifts) always comes from
the network and the PSOC server, so it is current without an update.

Change the icon in `scripts/make-art.cjs`, then run `npm run icons`.
